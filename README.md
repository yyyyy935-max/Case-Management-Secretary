# 사례비서

사례관리 담당자가 상담 기록을 쌓아 두면, 기관 양식 파일(한글 HWP, HWPX, Word)에 원본 모양 그대로 내용을 채워 주는 업무 도우미입니다.
기관 PC에서 실행하는 프로그램이며, 사례 기록과 채운 서류는 이 PC에만 저장됩니다.

- 요구사항: [docs/요구사항.md](docs/요구사항.md)
- 확정된 결정: [docs/결정사항.md](docs/결정사항.md)
- 현재 진행: **3단계 (사례 카드와 기록 쌓기, AI로 정리)**, [docs/3단계-보고.md](docs/3단계-보고.md). 이전 보고: [2단계](docs/2단계-보고.md), [1단계](docs/1단계-보고.md)
- 사례관리자로서 지킬 기준: [docs/사례관리자_기준.md](docs/사례관리자_기준.md)

## 실행 방법 (Windows)

### 1. Node.js 설치 (처음 한 번만)
1. https://nodejs.org 에 들어갑니다.
2. **LTS** 라고 적힌 버튼을 눌러 설치 파일을 내려받습니다.
3. 설치 파일을 실행하고 계속 [Next]를 눌러 설치를 마칩니다. 옵션은 바꾸지 않아도 됩니다.

### 2. 사례비서 내려받기
1. GitHub 저장소 화면에서 브랜치를 `claude/tender-sagan-brme53`로 고릅니다.
2. 초록색 **[Code]** 버튼을 누르고 **Download ZIP** 을 누릅니다.
3. 내려받은 ZIP 파일에서 마우스 오른쪽 버튼을 누르고 **압축 풀기** 로 원하는 폴더(예: `문서\사례비서`)에 풉니다.
   - **ZIP 파일을 더블클릭해서 그 안의 `시작.bat`을 바로 실행하면 안 됩니다.** 반드시 압축을 푼 폴더에서 실행합니다.

### 3. 실행
1. 압축을 푼 폴더에서 **`시작.bat`** 을 더블클릭합니다.
   - "Windows의 PC 보호" 창이 나오면 **추가 정보**, **실행** 을 차례로 누릅니다.
2. 처음 실행할 때는 필요한 파일을 내려받느라 몇 분 걸립니다(인터넷 필요).
3. 브라우저에 **사례비서** 화면이 열리고 표에 "실행 중"이 보이면 성공입니다.
   - 화면이 자동으로 열리지 않으면 Chrome 또는 Edge 주소창에 `http://localhost:4870` 을 입력합니다.
4. 끝낼 때는 검은 창을 닫습니다.

> 사례비서는 이 PC 안에서만 접속됩니다. 같은 사무실의 다른 PC에서는 접속할 수 없습니다.

### 문제가 생겼을 때
| 증상 | 해결 |
|---|---|
| "Node.js가 설치되어 있지 않습니다" | 1번을 다시 하고, PC를 다시 시작한 뒤 실행합니다. |
| "필요한 파일이 이 폴더에 없습니다" 또는 `Temp\...\package.json` 오류 | ZIP 안에서 바로 실행한 경우입니다. 압축을 푼 뒤 그 폴더에서 실행합니다. |
| "내려받기에 실패했습니다" | 인터넷 연결이나 기관 방화벽을 확인합니다. |
| "4870번 포트를 이미 쓰고 있습니다" | 사례비서 검은 창이 이미 켜져 있는지 확인합니다. 다른 프로그램이 쓰고 있으면 `config.local.json`의 `port` 값을 다른 숫자(예: 4871)로 바꿉니다. |

## 사례 카드 쓰는 법
> **가상 사례만 넣으세요.** AI에 보내기 전에 이름과 연락처를 가리는 기능은 5단계에서 만듭니다.

1. 화면 위쪽 **사례 카드**를 누르고, 왼쪽에서 **새 사례**를 만듭니다(가명).
2. **새 기록 넣기**에 상담, 가정방문, 전화 상담 메모를 붙여 넣고 **저장**합니다.
3. AI 키를 넣었다면 **저장하고 AI로 정리**를 누릅니다. AI가 사례 카드에 넣을 내용을 골라 **AI가 정리한 내용 확인**에 보여 줍니다. 내용마다 근거가 된 기록 원문 문장과 말한 사람이 함께 나옵니다.
4. 내용을 확인하고 **카드에 넣기**(필요하면 고친 뒤) 또는 **빼기**를 누릅니다. 담당자가 넣은 것만 사례 카드에 들어갑니다.
5. 기록 원문에서 근거를 찾지 못한 내용이나 담당자 의견은 프로그램이 미리 빼고, **프로그램이 뺀 내용**에서 이유를 볼 수 있습니다.

## 양식 채우기 쓰는 법
1. 화면 위쪽의 **양식 채우기**를 누릅니다.
2. **파일 선택**을 눌러 기관 양식 파일(한글 HWP, HWPX, Word)을 고릅니다.
3. 왼쪽에 양식이 나오고, 오른쪽에 항목 목록이 나옵니다. 항목마다 작성란, 체크 항목, 작성 안내 문구, 담당자 판단, 서명·동의란, 인적사항 등으로 색을 나눠 보여 줍니다.
   - 위쪽 **양식** 목록에서 한 파일 안의 여러 기록지(예: [양식3] 인테이크 기록지)를 고를 수 있습니다.
   - 오른쪽 위 단추를 누르면 그 구분의 항목만 보여 줍니다. **확인 필요**를 누르면 프로그램이 판단하기 애매했던 항목만 모아 봅니다.
4. 구분이 틀린 항목은 오른쪽 목록의 선택 상자에서 바꾸고 **고친 구분 저장**을 누릅니다. 같은 양식을 다시 올리면 고친 구분이 그대로 적용됩니다. 이 내용은 이 PC의 `data/templates/`에만 저장됩니다.
5. **내용 넣기:** 오른쪽 목록에서 항목을 누르면 입력 상자가 나옵니다. 체크 항목은 해당하는 것에 체크하고, 작성란은 글을 씁니다. "(   회차)"처럼 빈자리가 인쇄된 곳은 인쇄된 글이 미리 들어가 있으니 빈자리만 채우세요.
6. **채운 파일 만들기**를 누르면 원본과 같은 종류의 파일(`원래이름_채움.hwp` 등)을 내려받습니다. 원본 양식 모양이 그대로인지 확인한 결과, 좁은 칸처럼 확인할 점, 내용을 넣은 쪽의 원본과 결과 그림이 함께 나옵니다.
7. 원본 양식 파일은 바꾸지 않습니다. 올린 파일과 만든 파일은 이 PC 안에서만 다루고 따로 보관하지 않습니다.

## 설정 파일 (`config.local.json`)
처음 실행하면 `config.example.json`을 복사해 `config.local.json`이 만들어집니다. 메모장으로 열어 고칩니다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `port` | 화면 주소의 번호 | 4870 |
| `checkMark` | 체크박스에 표시할 기호 (`■`, `☑`, `V` 중 하나) | ☑ |
| `ai.provider` | AI 연결 방식. `gemini`(Google 직접) 또는 `openrouter` | gemini |
| `ai.apiKey` | AI 키. Gemini는 **결제가 연결된 유료 등급 키**만 쓰세요(무료 등급은 보낸 글이 학습에 쓰일 수 있음) | 비어 있음 |
| `ai.model` | 모델 이름. 사실 정리 기본값은 Gemini 2.5 Flash(OpenRouter는 `google/gemini-2.5-flash`). Gemini 직접 연결에서 비워 두면 flash 모델을 자동으로 고름 | 비어 있음 |
| `publicDataApiKey` | 공공데이터포털 API 키 (6단계부터 필요) | 비어 있음 |

`config.local.json`에는 API 키가 들어가므로 다른 사람에게 보내거나 GitHub에 올리지 않습니다(자동으로 올라가지 않게 설정되어 있음).

## 폴더 구성
| 폴더 | 내용 |
|---|---|
| `src/server/` | 프로그램 본체 (이 PC 안에서만 도는 서버) |
| `src/forms/` | 양식 읽기(HWP, HWPX, DOCX)와 항목 구분 |
| `src/cases/` | 사례 카드와 기록 저장, AI 정리와 근거 확인 |
| `src/ai/` | AI 연결(Gemini, OpenRouter). 연결 방식을 바꿀 때 이 폴더만 고침 |
| `src/forms/fill/` | 원본 형식 그대로 채우기(HWP는 rhwp, HWPX·DOCX는 XML 부분 교체)와 9.2 자동 검사 |
| `scripts/` | 양식 항목 구분 결과 표 만들기, AI 정리 평가 |
| `public/` | 브라우저 화면 |
| `data/` | 사례 기록 저장 위치 (GitHub에 올라가지 않음) |
| `test-data/` | 시험용 양식·가상 사례 (GitHub에 올라가지 않음). [test-data/README.md](test-data/README.md) 참고 |
| `tests/` | 자동 검사. `tests/fixtures/`에는 시험용 가상 양식을 만드는 코드가 있음 |
| `docs/` | 요구사항, 결정사항, 단계별 보고, 기준과 지침 |

## 개발자용
```bash
npm install
npm start        # 서버 실행
npm test         # 자동 검사 (test-data/forms에 표준 양식이 있으면 그것도 검사)
npm run typecheck
npm run analyze -- test-data/forms/양식.hwp   # 칸 분류 결과를 test-data/reports/에 표로 저장
npm run eval:extract            # 가상 사례 10개로 AI 정리 평가 (AI 키 필요, --fake는 키 없이)
```
