# 2단계 보고: 기관 양식에 원본 모양 그대로 채우기

- 날짜: 2026-11-24 (2026-11-24 견본 다시 만듦)

## 담당자가 볼 내용

**무엇이 되었나**
- 한글(HWP, HWPX)과 Word 양식 파일에 담당자가 정한 내용을 넣으면, 표 모양과 글꼴을 그대로 둔 채 채운 파일을 만들어 줍니다.
- 회색 안내 문구("※ 인테이크 욕구내용은…")가 있던 곳은 안내 문구를 지우고 검정 보통 글씨로 씁니다.
- 체크 항목은 고른 □만 ☑로 바뀝니다.
- 담당자 판단(욕구 점수, 선정 여부 등), 서명란, 인적사항은 나중에 AI가 채우지 않도록 막아 두었습니다.

**견본 파일 (가상 사례 이가상 어르신)**
처음 만든 견본에는 "가상 회기 내용 첫째 줄"처럼 시험용 글이 들어 있어 실제 기록지처럼 보이지 않았습니다. 78세 1인가구 어르신(월세 체납, 무릎 통증) 한 분의 사례로 실제 담당자가 쓰는 문장을 넣어 다시 만들었습니다. 이 사례는 지어낸 가상 사례입니다.

**한글에서 열어 확인해 주실 것**
1. 파일이 오류 없이 열리는가
2. 표 모양(칸 크기, 합친 칸, 테두리, 배경색)이 원본과 같은가
3. 넣은 글이 검정 보통 글씨인가 (회색, 기울임, 굵게, 밑줄이 남지 않았는가)
4. 회색 안내 문구가 있던 곳에 빈 줄이 남지 않았는가
5. 고른 □만 ☑로 바뀌었는가
6. 좁은 칸(사례관리 계획서 등)의 줄바꿈이 보기에 괜찮은가
7. 이대로 결재에 올릴 수 있을 만큼 기록지답게 보이는가

**담당자로서 직접 보고 고친 점**
- 과정기록지 "내용", 의뢰서처럼 원래 가운데 정렬인 칸에 긴 글을 넣으면 글이 가운데로 몰려 기록지답지 않았습니다. 여러 줄이거나 긴 글은 양쪽 정렬로 넣도록 고쳤습니다.
- 화면과 결과 확인 표에 "t7-r13-c0" 같은 개발용 번호와 "칸 역할" 같은 말이 보였습니다. 항목 이름과 현장 말로 바꿨습니다.

**아직 남은 문제**
- 과정기록지 "내용" 칸은 글이 칸 세로 가운데에 놓입니다. 원래 양식 설정이 그렇습니다. 한글에서 보기에 불편하면 위쪽 맞춤으로 바꾸는 기능을 넣겠습니다.
- 이 개발 환경의 문서 프로그램(LibreOffice)에서는 Word 견본의 ☑ 옆 글자("방문", "전화")가 빈 네모로 보였습니다. 파일 안 글자는 정상입니다. Word에서 열었을 때 같은 문제가 있는지 확인이 필요합니다.

## 개발 기록

## 1. 만든 것
| 형식 | 쓰는 방법 | 손대지 않는 부분 |
|---|---|---|
| HWP 5.x | rhwp(MIT)로 원본을 열어 대상 칸의 문단만 고친 뒤 HWP로 저장 | rhwp는 아무것도 고치지 않으면 원본의 모든 내부 스트림을 똑같이 저장함(확인함). 고치면 그 칸의 문단 기록과 글자 모양 목록만 바뀜 |
| HWPX | 압축 안의 XML 글에서 대상 칸 부분만 잘라 바꿈 | 다른 글과 압축 안의 다른 파일은 압축된 바이트까지 그대로 |
| DOCX | 위와 같은 방법(word/document.xml) | 위와 같음 |

- **화면:** 양식 칸 지도에서 칸을 누르면 값을 넣는 상자가 나온다. 체크 칸은 선택지에 체크하고, 글 칸은 글을 쓴다. **채운 파일 만들기**를 누르면 파일을 내려받고, 검사 결과·확인할 점·쪽 비교 그림이 함께 나온다.
- **안전장치:** 항목명·고정 문구 칸, 안쪽 표가 든 칸은 쓰지 않는다. 값을 정한 주체가 AI이면 판단·서명·인적사항 칸은 쓰지 않는다(4단계부터 쓰임, 지금 시험으로 확인함).

## 2. 요구사항 4.2 문제 해결
| 문제 | 해결 방법 | 확인 |
|---|---|---|
| 안내 문구 칸에 쓰면 회색 기울임이 남음 | 안내 문구 칸이거나 첫 글자가 회색·기울임이면, 같은 글꼴·크기의 검정 보통 글씨로 바꿔 씀(HWP·HWPX는 일반 글자 모양을 새로 만들어 붙임) | 서울 인테이크 "욕구내용" 칸, 가상 양식에서 회색·기울임 없음 확인 |
| HWP에서 줄 수가 줄면 빈 줄이 남음 | 남는 문단을 지움(rhwp의 문단 합치기 사용) | 서울 "욕구내용" 안내 13문단 → 2줄 입력 시 2문단만 남음 |
| 좁은 칸에서 줄바꿈이 어색함 | 칸 폭·높이와 글자 크기로 한 줄 글자 수와 줄 수를 어림해, 넘치거나 좁은 칸에서 줄이 바뀌면 경고. (4단계에서 AI에게 글자 수 한도로 넘겨줄 값) | 서울 "총 만원"(한 줄 약 3자), "사정일자" 칸 경고 확인 |
| 굵은 밑줄 서식 칸에 쓴 글이 굵은 밑줄로 나옴 | 빈칸이라도 남아 있는 글자 모양이 굵게·밑줄·취소선·회색·기울임이면 일반 서식으로 씀 | 서울 "기존 서비스 내역" 칸(굵게·취소선이 남아 있던 빈칸) 일반 서식 확인 |
| 내용이 늘면 표가 다음 쪽으로 밀림 | 막지 않고, 채우기 전후 쪽 수(rhwp 조판 기준)를 결과에 표시 | 서울 23→23쪽, 보건복지부 109→109쪽 |
| 특수 기호(선택 기호 등) | 손대지 않는 칸은 원본 그대로. 체크할 때는 해당 기호 한 글자만 체크 기호로 바꿈 | 서울 가구유형 "󰋫1인가구"만 "☑1인가구"로 바뀌고 나머지 󰋫는 그대로 |

추가로 찾은 문제: 안내 문구는 문단마다 정렬이 달라(첫 줄 가운데, 나머지 왼쪽) 첫 줄 정렬을 물려받으면 글이 가운데로 나온다. 그래서 안내 문구 칸은 가장 많이 쓰인 정렬을 모든 줄에 쓴다.

**바이트 단위 확인**
- 서울 HWP(22칸 채움): 원본 내부 스트림 10개 중 그림·요약 정보·미리보기 등 8개는 원본과 같음. 바뀐 것은 모양 목록(DocInfo: 일반 글자 모양 4개, 안내 문구 칸 정렬용 문단 모양 2개 추가)과 본문(채운 칸의 문단 기록, 높이가 바뀐 표 1개의 크기 정보)뿐. 그리고 아래 6장의 rhwp 표시 스트림 1개가 추가됨.
- 보건복지부 HWPX: 압축 안 파일 106개 중 105개가 **압축된 바이트까지 원본과 같음**. 바뀐 1개(section1.xml)도 앞 402,785자와 뒤 2,848,123자는 원본과 같고 채운 칸 부분만 바뀜.

**렌더 이미지 비교:** 화면의 쪽 비교와 시험에서 rhwp로 그린 원본·결과 쪽 그림을 비교했다. 채운 칸 외에는 같고, 채운 칸은 검정 보통 글씨로 들어갔다. 쪽 그림은 rhwp의 조판이라 한글과 조금 다를 수 있다.

## 6. 알려진 한계
- **rhwp 표시 스트림:** rhwp는 HWP를 저장할 때 자체 표시용 내부 스트림(RhwpLineSegTags, 40바이트)을 덧붙인다. 한글은 쓰지 않는 부분이다. 지우려면 파일 안 폴더 구조를 직접 고쳐야 해서 한글에서 안 열릴 위험이 있으므로 그대로 두었다. 한글에서 문제가 있으면 다시 다룬다.
- **쪽 수와 쪽 그림은 rhwp 조판 기준**이라 한글과 다를 수 있다.
- **아직 안 되는 것:** 표 밖 본문 문단 채우기(계약서 기간·서명 줄 등), 구역이 여러 개인 HWP, 안쪽 표가 든 칸, Word 내용 컨트롤 체크박스·기호 글꼴 체크박스, DOCX 쪽 수.
- **빈자리가 인쇄된 칸**("(   회차)", "총   만원")은 칸 전체 글을 새로 쓰는 방식이다. 화면에서 인쇄된 글을 미리 넣어 주므로 빈자리만 고치면 된다.
- 이 서버의 LibreOffice는 ☑를 컬러 이모지 글꼴로 그리면서 옆 한글을 빈 네모로 보여 주었다. 파일 안 글은 정상이며 Windows Word에서는 기호와 한글을 각각 다른 글꼴로 그린다.
- 칸의 원래 정렬을 따르되, 가운데 정렬 칸에 여러 줄이나 40자가 넘는 글을 넣으면 양쪽 정렬로 넣는다(견본을 다시 만들며 고침).
