# 3단계 보고 (진행 중): 사례 카드와 기록 쌓기, AI 사실 뽑기

- 날짜: 2026-11-24
- 상태: **실제 Gemini로 시험하는 것만 남음.** 사용자가 결제가 연결된 Gemini API 키를 넣으면 가상 사례 10개로 통과 기준("기록에 없는 사실 생성 0건")을 확인한다.

## 1. 만든 것
| 기능 | 내용 |
|---|---|
| 사례 카드 | 일반사항 9항목, 인물(대상자·가족·관계인), 욕구 14개 영역별 사실, 이용·연계 서비스. 칸마다 값, 근거 기록, 근거 문장, 말한 사람, 확인 여부를 저장 (요구사항 3.1·3.2) |
| 기록 쌓기 | 상담·방문·전화·회의 메모를 원문 그대로 날짜순 저장. 이 PC의 `data/cases/`에만 저장 |
| AI 사실 뽑기 | 새 기록을 Gemini에 보내 사실 후보를 받음. 지금 카드에 있는 사실을 함께 보내 같은 사실을 다시 내지 않게 함 |
| 걸러내기 (코드) | AI 후보를 아래 규칙으로 검사해 하나라도 어기면 뺌. 빠진 후보와 이유는 화면에 보여 줌 |
| 담당자 승인 | 후보마다 승인·고쳐서 승인·거절. 기존 값과 다르면 둘을 함께 보여 줌. 승인한 것만 카드에 들어감 (요구사항 3.3) |
| 직접 입력 | 담당자가 일반사항을 직접 넣거나 고치고, 사실을 지울 수 있음 |
| 화면 | 사례 카드 페이지. 맨 위에 "가상 사례만 넣으세요" 안내 |

## 2. 걸러내기 규칙 (AI가 지어낸 것을 막는 장치)
1. 정해진 항목(일반사항·욕구 영역·인물·서비스)에만 넣는다. 욕구 수준 점수·우선순위·선정 여부 같은 판단 항목은 아예 없다.
2. **근거 문장이 기록 원문에 그대로 있어야 한다.** (띄어쓰기·줄바꿈 차이만 허용)
3. **값에 든 숫자는 모두 근거 문장에 있어야 한다.** ("두 달"을 "2개월"로 바꾼 것은 허용)
4. 값의 낱말 중 절반 이상이 근거 문장에서 온 것이어야 한다. (근거는 맞는데 값을 다른 내용으로 바꾸는 것을 막음)
5. **진단명·낙인이 되는 말(치매, 우울증, 골절, 중독, 학대, 수급자 등 50여 개)은 근거 문장에 그 말이 그대로 있을 때만** 쓸 수 있다. (작성 지침: 진단을 짐작하지 않는다)
6. 고르는 항목(보호구분·가구유형 등)은 정해진 선택지여야 하고, 근거 문장에 그 선택지를 뒷받침하는 말이 있어야 한다. (예: 1인가구 ← 혼자·홀로·독거)
7. 담당자의 의견·추측은 사실로 넣지 않는다.
8. 인물의 관계(아들, 손자 등)가 기록에 나와야 한다.
9. 이미 있는 값은 다시 내지 않는다.

## 3. 가상 사례 10개
`tests/fixtures/virtual-cases.ts`. 실제 사례를 각색하지 않고 새로 지어냈다. 이름·연락처도 모두 가상이다.

| 번호 | 대상 유형 | 기록 형태 |
|---|---|---|
| 1 | 독거 어르신 | 짧은 메모, 3번에 걸친 기록 |
| 2 | 한부모 | 긴 서술 |
| 3 | 학교 밖 청소년 | 맞춤법이 엉망인 메모 |
| 4 | 지체장애 1인 가구 | 정보가 많이 빠진 메모 |
| 5 | 정신건강 위기 | 전화 기록, 가족 진술과 본인 진술, 담당자 소견이 섞임 |
| 6 | 결혼이민자 가정 | 통역을 거친 상담 |
| 7 | 조손 가정 | 2번에 걸친 기록 |
| 8 | 재혼·동거 가족 | 관계가 복잡한 서술 |
| 9 | 중장년 실직 1인 가구 | 숫자와 날짜가 많은 메모 |
| 10 | 노인부부 돌봄 | 담당자의 추측("치매가 의심됨")이 섞인 메모 |

사례마다 "뽑혀야 할 사실"(46개)과 "뽑히면 안 되는 말"(담당자 추측이나 기록에 없는데 지어내기 쉬운 말)을 정해 두었다. **사용자가 보시고 현장 메모처럼 어색한 곳을 고쳐 주시면 좋겠다.**

## 4. 지금까지 확인한 것 (가짜 AI)
실제 Gemini 대신, 일부러 지어낸 답을 섞어 내는 가짜 AI로 걸러내기를 시험했다.

| 시험 | 결과 |
|---|---|
| 가상 사례 10개 × 지어낸 답(금지어를 지어낸 근거로, 금지어를 진짜 근거에 붙여서, 없는 숫자, 담당자 의견) | **통과한 지어낸 사실 0건** (지어낸 근거 28, 담당자 의견 14, 없는 숫자 14 등 모두 걸러짐) |
| 걸러내기 규칙별 시험 | 진짜 근거·같은 뜻으로 바꾼 말·선택지 값은 통과, 지어낸 근거·다른 숫자·"무릎 골절"(근거: 무릎 아파서)·의견·없는 항목·뒷받침 없는 선택지는 걸림 |
| 화면 | 기록 저장 → 사실 뽑기 → 후보 고쳐서 승인·거절 → 카드 반영 확인 |
| Gemini 연결 코드 | 키는 요청 머리글로만 보내고 주소에 넣지 않음, 응답 형식 JSON 고정, 온도 0, 오류를 알기 쉽게 알림 (가짜 서버로 확인) |
| 자동 검사 | 36개 모두 통과 |

## 5. 앞으로 할 일
1. **사용자:** 결제가 연결된 Gemini API 키를 넣는다.
   - 개발 서버에서 시험할 때: 제가 띄우는 안전한 입력 창에 넣는다(채팅에 붙여 넣지 않음).
   - PC에서 쓸 때: `config.local.json`의 `ai.apiKey`에 넣는다.
2. 실제 Gemini로 `npm run eval:extract` 실행 → 10개 사례에서 기록에 없는 사실 0건인지, 걸러내기가 맞는 사실을 너무 많이 버리지 않는지 확인하고 보고한다.
3. 결과에 따라 지침·걸러내기 규칙을 고친다.

## 6. 알려진 한계
- 저장 데이터 암호화와 잠금 비밀번호는 5단계(개인정보)에서 붙인다.
- 가족 관계(혼인·동거 단위)는 7단계(가계도)에서 구조를 넓힌다. 지금은 인물마다 관계 이름만 있다.
- 걸러내기는 안전을 우선해 일부 맞는 후보도 버릴 수 있다(예: 근거와 말을 많이 바꿔 쓴 경우). 실제 Gemini 결과로 얼마나 버리는지 잰 뒤 조정한다.
