# 1단계 보고: 양식 읽기와 칸 지도 (읽기만)

- 날짜: 2026-11-23
- 시험 양식: 서울시 사회복지관 사례관리 표준 양식 모음 HWP 1개 파일 (양식 13종, 20쪽, 표 43개(셀 안 표 12개 포함), 칸 1,070개, 본문 채움 문단 8개)
- 양식 파일과 칸별 전체 결과표는 협회 저작물의 글이 들어가므로 저장소에 넣지 않고 사용자 PC의 `test-data/reports/`에만 둔다. 이 문서에는 개수와 항목명만 적는다.

## 1. 만든 것
| 기능 | 내용 |
|---|---|
| 양식 읽기 | HWP 5.x, HWPX, DOCX. 표, 셀, 가로·세로 병합, 셀 안 표, 셀 안 문단, 글자 모양(색·기울임·굵게·밑줄·크기), 셀 배경색, 셀 폭·높이, 좌우 테두리 |
| 칸 역할 분류 | 요구사항 4.1의 8가지 역할로 규칙에 따라 분류. AI는 쓰지 않음 |
| 화면 | 양식 칸 지도: 왼쪽 양식 표(역할별 색), 오른쪽 칸 목록(역할, 항목명, 분류 이유). 역할별 걸러 보기, 서로 찾아가기 |
| 결과표 | `npm run analyze -- <양식 파일>` → 칸마다 역할·항목명·이유를 적은 표 |

HWP는 kordoc으로 **메모리 안에서만** HWPX로 바꿔 읽는다. 원본 파일은 건드리지 않으며, 2단계에서 결과 파일은 원본 HWP에 직접 쓴다.

### 분류 규칙 요약
| 역할 | 판별 근거 |
|---|---|
| 안내문 칸 | 글자의 60% 이상이 회색이거나 기울임꼴 (예: 인테이크 "※ 인테이크 욕구내용은…", 사정기록지 "전화, 방문, 내방 등") |
| 서명·동의 | "(서명)", "(인)", "(직인)", "(서명 또는 인)" 자리 / "동의"가 들어간 체크 칸 / 동의서의 "필수 □", "선택 □" |
| 판단 칸 | 항목명이 선정, 욕구수준, 우선순위, 여력, 사례관리 수준, 면접결과, 점검결과, 평가결과, 달성도, 추후계획, 슈퍼비전 / 한 행에 한 자리 숫자가 3칸 이상 이어진 점수 칸 / 순위 번호가 인쇄된 행의 욕구영역 칸 |
| 인적사항 | 항목명이 성명, 이름, 생년월일, 주민등록번호, 연락처, 전화번호, 주소 / 배경색 있는 "클라이언트" 항목명 / 칸 안에 "성명:"이 인쇄된 칸 |
| 선택 묶음 | □ 등 체크 기호 또는 한글 문서의 특수 선택 기호(󰋫)가 있는 칸 / "방문/내방/전화/기타"처럼 고르는 목록 |
| 입력칸 | 빈칸 / "(   회차)", "(___세)", "총   만원", "의사소통 방법 :" 같은 빈자리가 인쇄된 칸 / 작성 항목이 인쇄된 칸 |
| 항목명 | 입력칸 왼쪽 또는 위에서 찾은 글 칸, 그리고 그런 항목명 여러 개를 묶는 제목 칸 |
| 고정 문구 | 채울 칸과 연결되지 않은 글 / 세로 테두리가 없는 빈 간격 줄 / 안쪽 표를 담은 칸 |

## 3. 잘못 분류한 칸 목록

### 3.1 개발 중 찾아서 고친 것
제가 1,070칸을 모두 확인하면서 찾은 오류이며, 아래는 모두 고쳤다.

| 칸 | 처음 분류 | 바른 분류 | 원인과 고친 방법 |
|---|---|---|---|
| 계획서 머리 표 2행 6칸 (t30-r1) | 입력칸 | 고정 문구 | 쪽 그림으로 확인하니 표 사이를 띄우는 보이지 않는 빈 줄이었음. 세로 테두리가 없는 빈 행을 간격 줄로 보는 규칙 추가 |
| 사정 결과 표 2·3순위 욕구영역 4칸 (t11·t29 r2·r3 c1) | 입력칸 | 판단 칸 | "우선순위" 머리글을 찾을 때 위의 "1" 칸에서 멈춤. 숫자 칸은 건너뛰게 고침 |
| 묶음 제목 22칸 (만남일시, 클라이언트 일반사항, 긴급 연락처, 주거 현황, 가족관계, 사회적관계, 1·2·3차 사후관리, 욕구영역·욕구사정 머리글, 실천계획, 실천계획 평가, 척도이용 사정, 만족도 "항목" 등) | 고정 문구 | 항목명 | 항목명 여러 개를 묶는 제목을 알아보는 규칙 추가 |
| 회기별 과정기록지 "내용" 칸 (t35-r4-c0) | 고정 문구 | 입력칸 | 간격 줄 규칙 첫 판이 표 폭 전체를 차지하는 한 칸짜리 행도 간격 줄로 봄. 한 칸짜리 행은 높이 6mm 미만일 때만 간격 줄로 보게 고침 |
| 여러 칸의 항목명 연결 오류 (역할은 맞았음) | — | — | 예: 인테이크 "사례관리 여력" 칸의 열 항목명을 몇 행 위의 "욕구내용"으로 잡음. 위로 올라가며 찾을 때 같은 폭으로 반복되는 행만 건너뛰게 고침 |

### 3.2 지금 남은 잘못 분류
**제가 확인한 범위에서는 0건이다.** 다만 아래 3.3은 제 해석으로 정한 것이라, 담당자 기준과 다르면 잘못 분류가 된다.

|---|---|---|---|---|
| 1 | "슈퍼비전" 칸 5곳 (과정기록지, 사례회의록, 평가서, 종결보고서, 사후관리보고서) | 판단 칸 | 슈퍼바이저가 쓰는 의견이라 사례 기록에서 옮겨 쓸 내용이 아님 | 기록에서 초안을 써도 된다면 입력칸 |

| 6 | "클라이언트" 항목명 | 배경색 있으면 인적사항, 없으면 입력칸 | 계획서·계약서 "담당 역할" 아래 "클라이언트" 행은 이름이 아니라 역할을 쓰는 칸 | 배경색이 없는 양식에서는 이 규칙이 맞지 않을 수 있음 |
| 7 | 사정기록지(체크리스트형) "가족1", "가족2" (기울임 글씨) | 안내문 칸 | 가족 구성원 이름·관계로 바꿔 쓰라는 자리 표시 | — |
| 8 | 작성 항목이 인쇄된 칸: 슈퍼비전 요청내용("- 슈퍼비전 주제 - 슈퍼비전이 필요한 배경"), 사후관리 계획("-사후관리 기간/횟수/빈도…") | 입력칸 | 인쇄된 항목은 그대로 두고 각 항목 뒤에 이어 쓰는 칸으로 봄 | 지우고 새로 쓰는 안내문으로 보면 안내문 칸 |

## 5. 알려진 한계
- **실제 기관의 HWPX·DOCX 양식으로는 시험하지 못했다.** HWPX는 표준 HWP를 바꾼 것과 가상 양식, DOCX는 가상 양식으로만 시험했다.
- DOCX는 글자에 직접 준 서식만 읽는다. 문서 스타일로 회색을 지정한 안내 문구는 안내문 칸으로 못 찾을 수 있다.
- 화면 왼쪽 미리보기는 표 구조를 다시 그린 것이고 실제 쪽 모양은 아니다.
- kordoc의 쪽 그림 기능은 이 파일을 23쪽으로 그린다(한글 기준 20쪽). 2단계의 쪽 수 비교는 한글에서 열어 확인해야 한다.
